Subnet and VLAN planner

Carve an address block into a slice per site, size each VLAN for its hosts plus growth, and get the subnet, mask, gateway and range for every VLAN.

    Address block

    Auto picks the smallest slice that fits the largest site. Pick a bigger slice to leave room for VLANs you add later.

    Sites

    How the math works
    
  
    An IPv4 address is a 32-bit number. The prefix length, the number after the slash, says how many of those bits name the network. The rest number the hosts inside it.
    
  
      
   
    • Block size is 2(32 − prefix). A /24 holds 28 = 256 addresses, a /23 holds 512, a /16 holds 65,536.
      • 
   
    • Usable hosts is the size minus 2. The first address is the network itself and the last is the broadcast, so a /24 has 254 usable.
      • 
   
    • The gateway takes one usable address. A VLAN that needs N hosts gets the smallest subnet with at least N + 1 usable.
      • 
   
    • Growth is added first and rounded up. 60 hosts at 25% is 75, plus the gateway is 76, so the VLAN gets a /25 with 126 usable.
      • 
   
    • Alignment. A subnet must start on a multiple of its own size. A /23 is 512 addresses, so it starts on an even third octet: 10.0.2.0/23 is valid, 10.0.3.0/23 is not. The same rule applies to the block you enter: 10.0.1.0/16 is not a network address, 10.0.0.0/16 is.
      • 
   
    • Largest first. The planner places each site's subnets from biggest to smallest, each on its own boundary. That packs them with no gaps and no overlaps, and leaves the free space in one run at the end of the slice.
      • 
   
    • Why not /31 or /32. A /31 has two addresses and no broadcast. It is meant for point-to-point links between two routers. A /32 is a single address, used for loopbacks. Neither can hold a gateway plus devices, so the smallest VLAN here is a /30: two usable, the gateway and one device.
